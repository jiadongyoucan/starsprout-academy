# 星芽 1.3 · 有温度的 HMI 与儿童空间设计

## 1. 目标
让家长感到「被理解、被支持」，让孩子感到「被欢迎、被陪伴」。不是加更多功能，而是把已有的课程、计划、伙伴和成长数据，翻译成有温度的语言、节奏和画面。

## 2. 对标与取舍
| 对标 | 借鉴 | 星芽的取舍 |
|---|---|---|
| Headspace | 柔和插画、呼吸感留白、温柔文案 | 不引入订阅/冥想课程；用插画和留白降低家长焦虑 |
| Khan Kids / Duolingo ABC | 大卡片、路径、角色、贴纸 | 不照搬游戏化积分轰炸；奖励只来自真实完成 |
| Toca Boca | 高饱和、手绘感、可触摸 | 儿童空间使用天空/草地/蜡笔贴纸，但不做开放世界 |
| Lovevery / 小步在家 | 家长视角的「今天做到一点就很好」 | 不做课程商城；保留体系化课程与计划 |
| Finch | 伙伴情绪与照顾 | 不制造愧疚：基础食物免费、离线封顶、无死亡 |
| Seesaw | 家庭成长记录 | 不做班级社交；保持家庭边界 |

## 3. 两种 HMI，同一套成长数据
### 家长空间（Parent Space）
- 语气：合作者、而非监工；「今天也辛苦了」「不必每天满分」。
- 结构：今日小安排 → 一句给自己的话 → 孩子的微小进步 → 可执行的一件事。
- 视觉：奶油纸张、极光、毛玻璃、衬线标题；卡片留白更大，数据降级为辅助。
- 温度组件：`今日一句`（可换一句）、`给自己的小纸条`、`家庭小确幸`（照片/伙伴/一句孩子的话）。
- 不做：排行榜、红色警告式 KPI、连续未完成羞辱。

### 儿童空间（Kid Space）
- 语气：短句、具体、可执行；「你慢慢来，我在旁边」「不会就是正在学会」。
- 结构：天空与草地 → 伙伴迎接 → 今日冒险路径（3 个停靠点）→ 大按钮开始 → 贴纸收藏。
- 视觉：高饱和天空蓝/草绿/太阳黄、粗描边、手绘波浪线、贴纸徽章、伙伴大图；字号 ≥ 16px，触控目标 ≥ 48px。
- 交互：一次只呈现一个主要动作；完成一个停靠点盖一个印章；不做密集导航和长文。
- 安全：家长视图入口始终可见；儿童空间不显示家长报告、联系方式、其他孩子。

### 平板学习端（Device）
- 保留大按钮、低干扰；增加伙伴与一句儿童悄悄话；把「学习准备」改成更温柔的「开始前，先深呼吸」。

## 4. 温度文案系统
- 类型：`parent_warm`（被理解）、`parent_humor`（轻松）、`parent_selfcare`（照顾自己）、`child_warm`（陪伴）、`child_brave`（面对不会）、`child_humor`（好笑）、`lesson_praise` / `lesson_retry`（具体反馈）。
- 规则：
  - 原创或公共谚语，不冒用名人名言；不制造焦虑、不比较孩子、不承诺效果。
  - 每天默认稳定一条（按日期 + 孩子 + 场景哈希）；用户可点「换一句」，不自动轮播。
  - 场景相关：低分不说「你真棒」，说「没答对也没关系，你的大脑刚刚长出一条新路」。
  - 家长文案避免说教；儿童文案避免反讽和成人幽默。
  - 幽默是温和的、可共情的，不拿孩子/家长开刀。
- 展示点：家长首页、儿童空间、课时完成、计划页脚、设备首页/计划；不做全屏弹窗，不打断任务。

## 5. 技术方案
- `src/infra/warmth-data.ts`：静态文案池（无外部依赖、可审校）。
- `GET /api/warmth?audience=parent|child&context=home|lesson|plan|child&fresh=1`：登录用户；按日期/孩子确定性选择，`fresh` 才随机换一条。
- `GET /api/device/warmth`：设备令牌；返回儿童向文案。
- 前端 `warmth` 组件：卡片/气泡，`aria-live="polite"`，每天缓存，手动刷新；儿童空间使用对话气泡。
- 奖励完成响应增加 `warmth`，庆祝层展示一句具体反馈；不改变发币逻辑。
- 徽章：从 `reward_events` 的 unit/plan 里程碑派生，用于儿童空间贴纸墙，不新增重复数据。

## 6. 验收
1. 家长首页有温度卡与可刷新的一句；文案不重复轰炸，刷新可用。
2. `#/child` 儿童空间有天空/草地/伙伴/路径/大按钮/贴纸；无家长数据；可返回家长视图。
3. 儿童空间在 390/320px 无横向滚动，触控目标足够大。
4. 设备端显示伙伴与一句儿童文案，不阻塞配对/学习。
5. 完成课时/单元/计划后出现具体、非评价性的鼓励；低分不羞辱。
6. 文案池无侵权引用、无焦虑/比较/虚假承诺。
7. 新增 API 有权限、校验、测试；旧流程不回归。

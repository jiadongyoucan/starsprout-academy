01执行摘要

先给结论：这不是一个「演示壳」。数据库里确实有 192 个课时、计划纠偏确实写审计、沙箱确实拦住了逃逸、照片确实按 0600 落盘并按家庭隔离。问题在于——文档描述的是 v1 的完整产品，代码交付的是「结构完整 + 局部占位」的版本，而且文档把不少「设计了」写成了「已验收」。

FINDING 01

教学模态只在 20% 的课时里成立

192 个课时都有 6–8 个 block，但「听 / 说 / 描红 / 钢琴 / 节奏」只出现在英语、汉字、钢琴课里。智趣思维与蒙氏工作共 72 个核心课时（40%）只剩故事、卡片、配对、选择题与回顾。

FINDING 02

审核输入侧失守

把「加微信」写成「加/微信」、把手机号写成「138/0013/8000」，就能零拦截通过；评论更是直接 approved，从不进入人工队列。

FINDING 03

生态只兑现了「人格」

专家人格确实注入系统提示；但连接器完全不在模型工具表里，技能只拼名字、定义从不进提示词。所谓「人格 + 提示词 + 技能」缺了两块。

FINDING 04

温度叙事在最关键处掉线

孩子离开 24 小时，情绪标签是「有点想你」，台词却回落成「今天心情很好」；房间装饰买了不显示，玩具效果从不生效。

FINDING 05

证据链不可复现

产品文档、QA 报告、README 三处都写了「浏览器 E2E / Chrome 157 CDP 实测」，但仓库里没有任何浏览器测试、脚本或截图。PWA 离线壳冷启动会白屏。

FINDING 06

指标章节零实现

北极星指标、D0/D7/D30/D90、审核通过率与平均时长，没有任何采集、聚合或导出。后台只有 12 个 COUNT。

公正起见：这些确实做到了

  • 192 课时严格等于 180 核心 + 12 公开；4 学段 × 5 学科 × 3 单元结构无缺口，每单元有可观察目标。
  • 每个课时 6–8 个 block（实测 108 / 45 / 39 分布），家长端与平板端共用同一份 block 渲染器（device.js 直接 import views/learn.js）。
  • 计划：19:00 Asia/Shanghai 提醒、21 天顺延、跳过留痕、plan_adjustments + 审计、一键纠偏 UI 全部可用。
  • 智能体：8 个工具真实注册且可执行；沙箱用独立子进程 + --permission，实测 process/require 为 undefined、死循环 800ms 终止。
  • 社区：待审状态机、禁止自审、课程必须关联已发布课时、编辑重审、举报隐藏均已落地。
  • 多端：6 位一次性码、设备令牌哈希落库与撤销即失效、照片 0600 + 随机名 + 跨家庭 404 + 30 天清理。
  • 伙伴：服务端判分、首通幂等、单元 +30 / 计划 +100、衰减封顶与下限、庆祝层焦点陷阱与 reduced-motion。
  • 工程：tsc --noEmit 通过；Docker 镜像可构建、容器健康检查通过；备份脚本可用。

02评审方法与证据

本报告不是读文档后的主观印象。每条差距都要求：文档原文可定位、实现可指到文件与行、行为可复现（必要时用运行时数据或负向输入验证）。

四层证据

  1. 规范层：以 docs/product.html（Product Spec v1.3）为主，companion-design.md / warmth-design.md 补充领域设计，DESIGN.md / architecture.html / qa.html / README 做交叉校验。product.html 内联了 14 张 base64 截图（文件 1.98 MB），先剥离样式与图片再逐节阅读。
  2. 实现层：通读 src/ 的服务端模块与 src/web/ 的前端视图，逐条定位承诺的实现点；对「声称有、实际无」的能力做全仓 grep 反证。
  3. 运行时层：真实启动服务并直接查询 SQLite，统计课时、block、单元、课程包；用 moderateContent() 对分隔符、软连字符、繁体做负向探测。
  4. 工程层：npm test、tsc --noEmit、docker build / docker run 健康检查，确认报告中的「已通过」到底能不能复现。
严重度定义　P0：与文档的核心承诺直接相反，或关键证据根本不存在（对外可信度受损）。P1：能力明显缩水、行为与描述不符，影响核心体验或治理闭环。P2：细节、文案、死代码、可访问性等可在迭代中清理的问题。

04五个系统性模式

把 55 条差距放在一起看，会发现它们不是随机缺陷，而是五种反复出现的生产方式。

PATTERN 01

演示态与生产态混在一起

公开课种子 autoApprove:true 与 demo 开关无关；「隔离审核」只在后续同步里成立。演示用的宽松路径没有在生产开关下被重新收紧。同类：影子账号、假 checksum。

PATTERN 02

文案先行，能力后置

「AI 辅助生成」「布置房间」「证书」「六种情绪」「不是实时监控」——文案先写进了界面与文档，但对应的数据、组件或行为没有跟上。用户读到的比系统能做到的多。

PATTERN 03

影子实现：代码在，路径不通

sha256 导入了但没调用；occupied 构造了但从没读取；sad 有类型但永远不可达；ring() 有实现但零调用；技能 definition 查出来但只用了名字。这类「死代码」会让静态阅读误判为已实现。

PATTERN 04

测试覆盖契约，不覆盖体验

83 个用例几乎都是 HTTP 契约与状态机断言：跨家庭 403、幂等、超时、422。没有一条断言「每课都有听说读写」「儿童字号 ≥16px」「审核能拦住变体」——所以文档里的体验承诺没有任何防线。

PATTERN 05

降级不声明

「离线可用」实际是「无 API Key 时用本地规则」；「浏览器 E2E」实际是人工点检；「SSE + 轮询兜底」在不支持 SSE 时反而没有轮询。降级路径没有被诚实地写进文档。

PATTERN 06

安全集中在「读」，薄弱在「写入口」

越权读取、照片隔离、沙箱逃逸都做得不错；但内容入口（社区、评论、公开专家）与审核规范化是薄弱面。攻击者不需要绕过 JWT，只需要在违禁词里加一个斜杠。

除了「文档 vs 实现」，文档之间也互相打架。这些不一致会直接影响验收判断，建议与代码修复一起收敛。
